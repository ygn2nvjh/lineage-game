# 右側步行四關鍵姿勢與母版校準 v0.9

入口 `/art-calibration.html?v=9`。本輪只處理男女右側步行，沿用固定 `hero-static-reference-20261029-v1`，不重畫人物、怪物或其他方向。原三視圖/v0.8候選保留在可展開區，原v0.7動作試場及正式/play亦保留。

## 本輪固定要求

嚴格沿用母版鎧甲、腿甲、靴型、身體比例與同一持劍手；近腿/遠腿身分固定。畫布、來源尺度、視角不逐格自動fit。原母版與分件指紋不變；這輪沒有重新生成美術圖片，所有畫面仍取自已公開的固定母版。上身部件含唯一完整武器，遠腿→近腿→上身的順序固定；不是拼不同姿勢的刀與身體。

四個關鍵相位：

1. 0%：近腳前接觸，遠腳在後開始抬起。
2. 25%：近腳支撐，遠腳抬起經過。
3. 50%：遠腳前接觸，近腳在後開始抬起。
4. 75%：遠腳支撐，近腳抬起經過。

按四張卡片可暫停在該姿勢；PNG下載把固定母版與四姿勢並列保存。可選男女、移動/原地、半速/正常/兩倍、骨架/支撐點、足底軌跡、連續相位滑桿。

## 與v0.8的實作差異

舊候選先旋轉腿再各自向下拉到地面，髖/膝連接與腳底速度沒有共同約束。這版先定世界腳底接觸點，再以來源固定長度的大腿/小腿求膝蓋及腳踝。靴子支撐時保持原方向。只旋轉/位移既有像素，沒有各自縮放或換裝。關節是人工標記的2D近似，不是假裝由圖像自動辨識的精準骨架。

`data/art/right-walk-v1.json` 為本輪唯一動作設定來源；40來源像素/循環、0.8秒/循環、50%支撐期、抬腳5來源像素。變速同時改位移與相位，不能只改播放速度。測試速度不是正式遊戲移速，本輪未調正式移動。

在支撐期，角色每前進多少，腳相對身體就向後移多少，世界接觸點保持固定。兩腳相位差半個循環，會確實交換前後，而非永遠同一腳領先。遠腳依原視角位於稍高的地面線。上身有1～3來源像素的重心起伏，沒有修改造型或逐格變身高。走到右側從起點重播是試走循環，不是網路拉回。

`src/hero-walk-motion.mjs` 是純相位/雙節骨解算及同源部件繪製；`src/hero-right-walk.mjs` 是獨立校準介面。完整角色先畫在透明actor layer，再一次合成到地面。靴子在最終畫面座標對齊取樣，避免多次小數變換造成像素差。支撐點/骨架標記屬診斷覆層，量測腳底時關閉，避免將抗鋸齒標記誤判成靴子變形。

## 校準證據與限制

- `node scripts/audit-right-walk.mjs`：每角色4,000個相位樣本，檢查固定母版、交換支撐/領先、骨長不伸縮、腳底計算點不漂移、來源尺度1、唯一武器上身。報告在 `assets/art-calibration/right-walk-audit-v1.json`。
- Node單元包含過大步幅的反例，確保骨架不可達時會報誤差，不能以拉長腿掩蓋。
- 實際Chromium手機390×844與桌面960×900，男女近/遠各取6個支撐相位。透明角色圖層上採樣實際靴底，48個樣本的支撐點固定，已測靴底截線像素不變。這不是所有設備、全部影格絕對無抖動的保證。
- `tests/hero-right-walk-browser.cjs` 自動產出 `right-walk-raster-v1.json`，記錄取樣範圍、每組像素變體數與來源指紋；數學報告不冒稱渲染報告。
- 建置驗證兩份報告的model/config/UI/分件來源SHA256，變更後沒重跑對應檢查會拒絕。正常網站建置不需要Chromium/Python。
- 舊固定母版三視圖及PNG下載回歸測試保留。母版、原候選圖集、正式人物/戰鬥/雲端/連線均不變。

動作美感、膝蓋輪廓與裝甲關節遮擋仍待使用者看圖驗收。計算長度固定不能代替美術判斷；需要補畫關節露出部分時，仍需沿母版校準，不能偷偷改裝。其他方向、攻擊、受擊、倒下、收步尚未以本套新步行重製，不擴大本輪範圍。
