# 人物固定母版校準 v0.8（待美術驗收）

入口 `/art-calibration.html?v=8`。使用者指出靜態稿優於動態版：腿變細、鎧甲換款。原v0.7技術檢查只比較當批素材內部與緊鄰前版，不能證明仍忠於最初靜態設計。本頁補上固定身份母版，舊試場/正式遊戲均保留。

## 固定來源，禁止母版自動漂移

母版是 `assets/art-review/characters.webp` 中右側展示的「新站姿」，不是圖上的舊原版動作。原素材包含男/女各正、側、背三張，側面由原左向鏡像為右向。每視圖只一次等比正規化至112來源像素身高；以兩腳中心定位，圖片外框/刀尖不決定身體中心。母版足底與原站姿保留。

`data/art/hero-reference-lock.json` 鎖定原檔、正規化母版、分件、metadata的SHA256。此為本輪固定參考，並非已宣稱使用者批准全部動畫。來源、遮罩、比例或標記更動需明確新參考版本，不能每次拿最新版覆蓋。`prepare-hero-calibration.py` 對既有鎖定內容不同會拒絕，不能自動升母版。

## 三欄校準與可保存圖

固定母版／目前動態v0.7／母版分件候選，同倍率同地面。男女三視圖、站姿與步行、50%疊圖、人工頭/軀幹框、逐格暫停、12格循環、放大自有橫向捲動。PNG下載會把當前性別三視圖全部排成三欄校準圖，並保留母版ID，可在每次改動後留檔比對。

表格像素為正規化來源單位，112來源高對應既有ART_MOTION顯示倍率，不直接當手機螢幕像素。頭/軀幹矩形是人工估測，外框含刀與髮尾；不同站姿會影響外框/遮擋，像素差不能當美術分數。母版分件候選的待機與母版像素一致，故差異為0，這不代表新的走路已獲美感驗收。

## 本輪候選如何保留裝備

沒有重新生成圖片。每方向以人工遮罩把原像素分配為上身（含唯一完整武器）、遠腿、近腿；重疊縫線近腿優先，每像素只歸一個部件。重組靜態圖須與母版完全一致，任何遺失/重複/改色都拒絕。動作只對同一套大腿、小腿/靴像素做關節旋轉與位移，不另外拉長、拉窄、換甲或給遠腿重新上色。關節預烘焙在離線圖集中，瀏覽器每人只取一張完整影格，不拼不同姿勢的身體/刀。

站姿直接使用完整母版；步行為12格×3方向×2角色。共78個影格。膝關節銜接、抬腳節奏、滑步與停止轉換仍待下一步目視確認。這是動作候選，不是宣稱完成全動畫。

**攻擊、受擊、倒下、收步尚未依母版重製。** 頁面明列未完成，不借舊v0.7鎧甲冒充已完成；原可操作試場v0.7與正式/play均未被此候選替換。怪物也不在本輪重畫。

## 驗證與重製

- `python3 scripts/prepare-hero-calibration.py`：可重複的固定來源裁切、同尺度分件，既有母版內容不同即拒絕。
- `PLAYWRIGHT_MODULE=playwright CHROMIUM_PATH=/usr/bin/chromium node scripts/bake-hero-calibration.cjs`：以既有分件烘焙候選PNG及metadata；離線環境需Playwright/Chromium。
- Pillow將候選PNG無損編碼為同名WebP；所有打包WebP及metadata保留在公開原始碼。
- `python3 scripts/audit-hero-calibration.py`：固定指紋、部件重組、站姿一致、頭部穩定、影格完整、裁切與支撐腳檢查，產出audit-v1.json。
- 一般Node建置只核對已打包圖集/metadata/母版指紋與報告，不需Python/瀏覽器。檔案改過但未重跑報告會拒絕。
- `tests/hero-calibration.py`：改母版指紋、漏影格與改待機外觀的負向檢查。
- `tests/hero-calibration-browser.cjs`：手機/桌面六視圖像素一致、動畫/暫停/逐格、放大不溢出頁面、PNG下載、未完成項目與零WebSocket。

未來人物批次：保留此母版ID，新的候選與新增動作均指向它，重新輸出同格式校準圖及報告。只有明確授權改角色設計才開新母版版本。既有 `art-production` 的裁切/比例/腳底檢查仍保留；身份校準是新增的一層，不能以其中一種代替另一種。
